# v0.14 design decisions: batched queries

Summary of the batched-queries work that shipped in v0.14
(#148 + #149). Full design rationale in
docs/v0.14-batched-queries-design.md.

## What landed

**Two related changes, both YAML-configurable, both default-off:**

### Change 1: per-baseline `batch_size` consumption

Adapters with library-level batching support (nbn, pomegranate)
override `query_batch(list[Query]) -> list[Posterior]` to use
their library's batched API. Sequential adapters (pyro, pgmpy)
inherit the default loop-over-`query()` helper.

The selector emits `list[list[Query]]` — groups of queries sharing
(target, evidence_vars), chunked by `batch_size`. The runner
dispatches each group through `adapter.query_batch`, amortizes
the timing per query, and stamps `batch_size` on each row.

YAML:
```yaml
baselines:
  - { library: nbn, mechanism: cat, param_method: mle, inference_method: ve, batch_size: 512 }
  - { library: pyro, mechanism: empirical, param_method: mle, inference_method: importance, batch_size: 1 }
```

Default `batch_size: 1` preserves pre-batching behavior — every
existing benchmark behaves identically (B=1 dispatch routes through
the original `adapter.query()` code path).

### Change 2: `batch_sizes` sweep (speed benchmark)

Top-level YAML field. The CLI iterates the sweep; batchable
baselines run once per sweep value (with `batch_size` overridden
to that value); non-batchable / pinned baselines run once.

YAML:
```yaml
n_batch_queries: 10240
batch_sizes: [1, 8, 32, 128, 512, 1024]
```

Closes #148 (speed benchmark) and #149 (auto-batch question:
resolved as "no auto-batching in existing benchmarks" — they stay
at the n_batch_queries=1 default; the speed benchmark is the
dedicated sweep consumer).

## Auto-detection rule

The sweep dispatcher uses each adapter's class-level
`supports_batched_queries: bool` flag:
- True: nbn, pomegranate — run at every sweep value
- False: pyro, pgmpy — run once at batch_size=1

Explicit YAML `batch_size: N` always wins — a pinned baseline
runs once at its pinned value regardless of capability.

## Schema additions

- `CellResult.batch_size: int = 1` — stamped per row
- `BaselineSpec.batch_size: int = 1` + `batch_size_pinned: bool`

Existing parquets without `batch_size` read as null → 1
on consumers.

## Status semantics under batching (§4.7 + amendment)

- B=1 path: preserves pre-batching elapsed-on-failure timing
  (backward compat)
- B>1 path: failed batches are atomic — all B rows get
  status=oom/error with query_time_s=NaN
- Cell timeout mid-batch: K sentinels (one per query position),
  not K×N
