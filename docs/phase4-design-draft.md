# Phase 4 — BnlearnProblemSource

**Status:** Design draft (pre-implementation)
**Depends on:** Phase 2 (TopologicalAllocator, merged in PR #124)
**Related:** issue #109 (v0.13 roadmap)

## 1. Background

Phases 2 and 3 introduced topology-aware query selection that works
against any DAG with a fitted CPD set. The benchmark data so far has
been synthetic: DAGs generated by `make_synthetic_bn()` with parameters
fit from sampled data.

Phase 4 adds **real Bayesian networks** as a problem source: the
bnlearn repository at https://www.bnlearn.com/bnrepository/ provides
canonical reference networks of three kinds:

- **Discrete networks** (e.g., ASIA, Alarm) distributed as `.bif`
- **Gaussian networks (GBN)** (e.g., ECOLI70) distributed as `.rda`/`.rds`
- **Conditional Linear Gaussian networks (CLGBN)** (e.g., Sangiovese) distributed as `.rda`/`.rds`

`BnlearnProblemSource` loads these networks, generates train/test data
by forward-simulation from the loaded CPDs, and emits `BenchmarkProblem`
objects compatible with the existing pipeline. The basic benchmark
(TopologicalAllocator from Phase 2) consumes them with no changes to
the selector or the runner.

## 2. Distribution and storage

### 2.1 Discrete networks — on-demand download

Discrete networks ship as `.bif` files at:
`https://www.bnlearn.com/bnrepository/<network>/<network>.bif.gz`

`BnlearnProblemSource` downloads on first use, caches to
`~/.cache/nbn/bnlearn/<network>.bif`. Subsequent runs use the cache.

### 2.2 Gaussian + CLG networks — pre-converted, bundled

The R-native `.rda`/`.rds` formats can't be read natively from Python.
We pre-convert these files once to a Python-readable JSON format using
R (with the `bnlearn` and `jsonlite` packages), and commit the converted
JSON files to the repo at `benchmarking/data/bnlearn/`.

The conversion script (`scripts/convert_bnlearn_continuous.R`) is
committed to the repo alongside the converted files. Re-running it
requires R + `bnlearn` + `jsonlite` packages; this is a one-time
maintenance task when bnlearn updates a network.

Users do not need R for normal use — they just need the bundled JSON files.

## 4. Data flow

For each `(network, seed)` pair in the YAML config, the source:

1. **Loads** the DAG + CPDs from the bundled JSON (gaussian/clg) or
   downloaded `.bif` (discrete).
2. **Forward-simulates** `n_train` rows for `train_data` and `n_test`
   rows for `test_data`. Random state seeded by `seed`.
3. **Constructs** a `BenchmarkProblem` with the loaded structure, the
   sampled data, `true_model` set to the loaded pgmpy model, and
   `family` matching the network kind.
4. **Yields** the problem to the runner.

Forward sampling per kind:

- **Discrete**: `pgmpy.sampling.BayesianModelSampling(model).forward_sample(size=N, seed=seed)`. Native pgmpy support.
- **Gaussian**: try `pgmpy.models.LinearGaussianBayesianNetwork.simulate(N)` first; fall back to custom ancestral sampling (numpy-based) if unavailable or buggy.
- **CLG**: custom ancestral sampling with the discrete-before-continuous topological constraint (~30-50 LOC). For each node in topological order:
  - If discrete: sample using the discrete CPD given parent values
  - If continuous: identify the discrete parent configuration `d`, look up the corresponding `(β_d, μ_d, σ_d)`, sample from `N(β_d^T·continuous_parents + μ_d, σ_d²)`

## 5. R-side conversion script

`scripts/convert_bnlearn_continuous.R` performs the one-time
`.rda`/`.rds` → JSON conversion. For each gaussian/clg network:

```r
library(bnlearn); library(jsonlite)

network_name <- "ecoli70"  # iterated over the list
bn <- readRDS(paste0("path/to/", network_name, ".rds"))  # or .rda + load()

# Extract DAG edges + CPD parameters into a JSON-compatible structure
result <- list(
  name = network_name,
  kind = "gaussian",  # or "clg"
  nodes = nodes(bn),
  edges = arcs(bn),
  cpds = lapply(nodes(bn), function(node) {
    # Per-kind extraction (Gaussian: intercept/coefficients/sd; CLG: nested by discrete config)
    ...
  })
)

write_json(result, paste0("benchmarking/data/bnlearn/", network_name, ".json"),
           pretty=TRUE, auto_unbox=TRUE)
```

### 5.1 JSON schema (Gaussian node)

```json
{
  "name": "<node_name>",
  "type": "gaussian",
  "parents": ["<parent_node>", ...],
  "intercept": <float>,
  "coefficients": {"<parent>": <float>, ...},
  "sd": <float>
}
```

### 5.2 JSON schema (CLG continuous node)

bnlearn stores CLG continuous parameters natively as a `[coef × config]`
matrix plus a per-config `sd` vector — **not** a list of explicit
`{discrete_config, ...}` records (the original draft assumption). We keep
that compact native layout: parallel arrays indexed by a flat config id.

```json
{
  "name": "<node_name>",
  "type": "clg_continuous",
  "discrete_parents": ["<dp1>", "<dp2>", ...],
  "continuous_parents": ["<cp1>", ...],
  "dlevels": {"<dp1>": [<state1>, <state2>, ...], "<dp2>": [...], ...},
  "intercepts": [<float>, ...],
  "coefficients": {"<cp1>": [<float>, ...], "<cp2>": [...], ...},
  "sds": [<float>, ...]
}
```

All array fields (`intercepts`, each list in `coefficients`, `sds`) have
length `K = product of |dlevels[dp]|` over all discrete parents. The
config index `i ∈ [0, K)` decodes to a discrete-parent state assignment
by:

```python
def decode_config(i, discrete_parents, dlevels):
    cfg = {}
    for dp in discrete_parents:
        n_states = len(dlevels[dp])
        cfg[dp] = dlevels[dp][i % n_states]
        i //= n_states
    return cfg
```

This matches bnlearn's native encoding — the **first discrete parent
varies fastest**, exactly as `expand.grid(dlevels)` enumerates (verified
on mehra's `t2m`: Year × Month × Hour = 5760 configs). The compact form
is far smaller than explicit per-config records (mehra's `wd` node alone
has K = 66,960; ~5.8 MB compact vs ~35.7 MB explicit) and faithful to the
native R structure.

Pure Gaussian nodes inside CLG networks (e.g. healthcare has one) use the
§5.1 schema. Discrete nodes inside CLG networks use the §5.3 schema.

### 5.3 JSON schema (discrete CPD in CLG networks)

A discrete node's `bn.fit$prob` is a multidimensional `table`: axis 1 is
the node's own states, axes 2.. are its parents in `parents` order. We
serialize it column-major (R's native flatten) plus enough metadata to
reconstruct the array in Python:

```json
{
  "name": "<node_name>",
  "type": "discrete",
  "parents": ["<parent1>", ...],
  "states": [<own_state1>, ...],
  "prob_dim": [<n_own_states>, <n_parent1_states>, ...],
  "prob_dimnames": {"<node>": [...], "<parent1>": [...], ...},
  "prob": [<float>, ...]
}
```

Python reconstructs with `np.array(prob).reshape(prob_dim, order="F")`,
where axis 0 indexes the node's own states.

## 6. YAML surface

```yaml
problem_source:
  type: bnlearn
  networks: [asia, alarm, insurance, ecoli70, sangiovese]
  seeds: [0, 1, 2, 3, 4]
  n_train: 5000
  n_test: 1000

selector:
  type: topological
  target_allocation: {hub: 0.30, cut: 0.25, terminal: 0.25, random: 0.20}
  # ... rest matches existing topological selector knobs

n_queries_per_cell: 64

baselines:
  - {library: pgmpy, mechanism: discrete_ve, param_method: mle, inference_method: ve}
  - {library: pgmpy, mechanism: lg_predict, param_method: mle, inference_method: predict}
  - {library: pomegranate, mechanism: discrete_ve}
  - {library: pyro, mechanism: empirical, inference_method: importance}
  - {library: nbn, mechanism: cat_ve}

measurement: AccuracyAndTiming
per_cell_timeout_s: 60
```

`networks:` is an explicit list of network names. No size-class
shortcuts in this iteration — users list networks they want.

The runner produces (network × seed × baseline × n_queries) cells.
Each network's `family` determines which baselines apply (discrete-only
baselines skip gaussian networks, etc., via existing applicability
machinery in `benchmarking/core/applicability.py`).

## 7. Data model

`BenchmarkProblem` fields populated by `BnlearnProblemSource`:

- `name`: network name (e.g., `"asia"`)
- `dag`: list of edges from the loaded model
- `variables`: dict mapping node name to `(type, cardinality_or_None)`:
  - Discrete nodes: `("discrete", n_states)`
  - Gaussian / CLG continuous nodes: `("continuous_gauss", None)` (Gaussian) or `("continuous_lg", None)` (CLG continuous)
- `train_data`: dict[node, torch.Tensor] of shape `(n_train,)`
- `test_data`: dict[node, torch.Tensor] of shape `(n_test,)`
- `queries`: empty list (selector populates)
- `seed`: the YAML seed value
- `family`: `"discrete"` / `"continuous_gauss"` / `"clg"`
- `problem_id`: same as `name`
- `true_model`: the loaded pgmpy model object (for oracle)

The cache key for selectors after Phase 3's fix is
`(family, problem_id, seed)` — works correctly for bnlearn problems
since each `(network, seed)` is a distinct entry.

## 8. Oracle compatibility

The existing oracle (`benchmarking/core/oracle.py`) dispatches on the
**target node's kind**, not the network's family (confirmed in Stages 2-3):

- **Discrete target**: `filter_ground_truth` does exact-match rejection
  on `problem.ground_truth.samples` (a pre-sampled reference pool). Used
  for discrete queries in both discrete and CLG networks.
- **Continuous target**: `forward_with_clamp_posterior_samples` calls
  `problem.true_model.sample(n, evidence)` for evidence-clamped ancestral
  sampling. Used for continuous queries in both Gaussian and CLG networks.

Implications for `BnlearnProblemSource`:

- **Discrete networks**: populate `ground_truth.samples` by
  forward-sampling `n_reference` rows in topological column order (mirrors
  `SyntheticProblemSource._ensure_gt_samples`). `true_model` is the loaded
  pgmpy `DiscreteBayesianNetwork`.
- **Gaussian / CLG networks**: build a `_BnlearnContinuousModel` whose
  `.sample(n, evidence)` does ancestral sampling with evidence-clamping.
  This object doubles as both the data generator (no evidence) and
  `problem.true_model` (with evidence), so continuous targets get accurate
  ground truth with **zero oracle changes**. CLG networks additionally
  populate `ground_truth.samples` for their discrete-target queries.

Stage 3 verified this end-to-end: `forward_with_clamp` returns finite
samples for both marginal and evidence-clamped queries on ecoli70
(Gaussian) and sangiovese (CLG).

## 9. Family naming

Three families:
- `discrete`: existing, used by both synthetic and bnlearn discrete networks
- `continuous_gauss`: NEW family name for pure Gaussian bnlearn networks (distinct from synthetic `continuous_lg`)
- `clg`: NEW family name for Conditional Linear Gaussian bnlearn networks

Rationale: synthetic `continuous_lg` is technically a linear Gaussian
network, but parameter generation differs from bnlearn's. Keep names
distinct so the parquet shows source clearly. Readers can distinguish
"synthetic LG at n=100" from "ECOLI70 with 46 nodes" downstream.

`continuous_gauss` and `clg` are **reporting** family values — they appear
on `problem.family` and in the parquet's `family` column. They do **not**
need to be added to `applicability.py`: adapters' `is_applicable` infer the
gating family from the per-node variable *kinds*
(`all continuous → continuous_lg`, `mixed → hybrid`), not from
`problem.family`. So a Gaussian network gates as `continuous_lg` and a CLG
network gates as `hybrid` (verified in Stage 4's smoke). The per-node type
must therefore be the literal `"continuous"` (not `"continuous_lg"`), or the
inference falls through to `hybrid` and the LG baselines never run.
