# Oracle methodology (paper §3 reference)

Source-of-truth synthesis for the paper's §3 methodology section (issue
#137). Originally transcribed from the #137 investigation (2026-06-03);
rewritten for the exact discrete oracle (D1, 2026-10). The implementation lives in `nbn/bench/core/oracle.py`; the
verification suite in `tests/integration/test_bnlearn_sanity.py`.

## 1. What the oracle is

Every accuracy metric in the paper is measured against an **oracle
posterior** computed from the known data-generating model (the problem's
`true_model`). Since the D1 fix (v0.20.x) the oracle is **exact wherever
exact inference is feasible** and Monte-Carlo otherwise, and every accuracy
row records which reference scored it in the `oracle` column:

| `oracle`    | used for | method | error |
|-------------|----------|--------|-------|
| `exact_ve`  | discrete target, all-discrete ancestral closure of `{T} ∪ E` (synthetic `discrete`, bnlearn `.bif` networks, all-discrete corners of hybrid nets) | variable elimination on the true CPTs | none (float64) |
| `lw`        | continuous targets; discrete targets whose closure has a continuous node (hybrid, CLG) or whose elimination exceeds the size cap | likelihood weighting on the true model | MC, ~`1/sqrt(ESS)` |
| `rejection` | discrete target when the true model is absent or cannot score the evidence | legacy rejection filter on the reference pool | MC, large (see §2.1) |

It remains a *defined reference*: all methods are measured relative to
inference on the data-generating model whose structure and parameters we
control. Rows with `oracle == "rejection"` should be excluded from headline
numbers (no shipped benchmark produces them: every problem source populates
`true_model`).

## 2. The oracle functions

All live in `nbn/bench/core/oracle.py` (+ `nbn/bench/core/exact_discrete.py`)
and are invoked by `AccuracyAndTiming`
(`nbn/bench/measurements/accuracy_timing.py`). Every draw runs under a seed
derived from `(problem_id, seed, query index)` (`nbn/bench/core/seeding.py`),
so the reference of a query is identical for every baseline of the cell and
across reruns.

### 2.0 Discrete targets — `discrete_oracle` (exact VE → LW → rejection)

1. **Exact tier (`exact_ve`).** The true model's CPTs are tabulated
   (`mechanism.forward(...)` for the synthetic NBN true model; `TabularCPD`
   values, axes in `state_names` order, for pgmpy / bnlearn) and
   `P(T | E=e)` is computed by log-space variable elimination over the
   ancestral closure of `{T} ∪ E` (barren nodes sum to one), greedy
   min-weight order. The plan is checked before any tensor is built; a clique
   above `2**23` entries raises and the query falls to the LW tier. The
   implementation is deliberately independent of `nbn.inference` and of
   pgmpy's VE — both are *methods under test*, and a shared code path would
   score their bugs as perfect answers. It is pinned against brute-force
   enumeration and pgmpy VE in `tests/unit/v013/test_oracle_exact_discrete.py`.
   The evidence-equals-target case returns the delta; zero-probability
   evidence yields no reference (`no_result`).
2. **LW tier (`lw`).** The target's self-normalised weighted histogram over
   likelihood-weighting particles from the true model (no resampling step).
   Particles are drawn until the ESS reaches the problem's `n_reference`
   (the config's `source.n_reference`, i.e. the reference-pool size), capped
   at `10 · n_reference` particles; an ESS below 100 → no reference. This
   replaces the old `±0.5σ` window on continuous evidence, which estimated
   `P(T | |E-e| < σ/2)` rather than `P(T | E=e)`.
3. **Rejection tier (`rejection`).** The legacy filter of §2.1, kept only as
   an explicit, flagged fallback.

### 2.1 Legacy discrete fallback — `filter_ground_truth` (rejection sampling)

Exact-match rejection on a forward-sampled joint reference pool
(`problem.ground_truth.samples`, `n_reference` rows — the synthetic discrete
pool used to be a hard-coded 5,000 rows that ignored the config). P(target |
evidence) is the empirical target distribution among pool rows matching the
evidence; continuous evidence nodes match within `eps_factor=0.50` standard
deviations. If fewer than `n_eff_min=10` rows survive the filter, the oracle
returns `None`. With 10-50 survivors the per-query TV error of this reference
is 0.05-0.07 — larger than many method gaps (a 1.9x TV gap was reported as
1.1x) — which is why it is no longer the default.

### 2.2 Continuous / CLG targets — `conditional_posterior_samples` (likelihood weighting)

Likelihood weighting on the ground-truth parameters. Particles are drawn by
ancestral sampling with the evidence clamped. Each particle is weighted by
`Π_{j∈E} p(e_j | pa_j)` under the true model, and `n_oracle_samples=2000`
(the `AccuracyAndTiming` constructor default) draws are resampled by weight.
This is consistent for `p(T | E=e)` for any mechanism family. Implementation
details:

- **Pruning:** only the ancestral closure of `{T} ∪ E` is sampled. No other
  node can change the posterior, and at n=10000 this made the oracle about
  100× cheaper than sampling the whole network.
- **Adaptive particle budget:** particles are drawn until the effective
  sample size reaches `n_oracle_samples`, capped at `50 · n_oracle_samples`.
- **Constant weights:** when every evidence node's ancestors are observed,
  the weights are constant and the particles are returned without
  resampling. That's the exact case the previous oracle covered.
- **Too few effective particles:** if the ESS stays below 100, the oracle
  returns `None` and the cell is **absent, not zero**. This mirrors the
  discrete `n_eff_min` rule.

**Correction (#288).** Up to v0.18 this oracle was *clamped ancestral
sampling alone*, and this section claimed it drew from the conditional. It
doesn't: clamping samples `p(T | do(E=e))`, which differs from `p(T | E=e)`
whenever an evidence node has an unobserved ancestor d-connected to `T`, for
example evidence downstream of the target.

Against exact Gaussian conditioning on `continuous_lg`, n=100:
- the clamped oracle was off by W1 up to 0.67 (target sd 0.93) on a hub
  query with three observed descendants;
- the LW oracle is within 0.012–0.106 on every query (the reference's own
  noise).

Continuous-target results produced before the fix need rescoring.

## 2.3 How a posterior is scored against the reference (D2, D3)

* **Discrete targets:** TV and JSD/log 2 between the reference probability
  vector and the method's. A method whose vector has a different length
  (e.g. a CPT on a truncated state grid) is an error, not `not_supported`.
* **Continuous targets:** W1 and the two-sample KS statistic between the
  oracle's `n_oracle_samples` (S = 2000) draws and the method's posterior
  samples **resampled to the same S** with a seed derived from the query
  (subset without replacement when the method returned more, draws with
  replacement when it returned fewer). Both metrics are bin-free.
  Resampling equalises the *oracle's* noise, not the method's: a method
  must return **at least S draws** for its score to be noise-comparable
  (pyro at 50 draws scores W1 ≈ 0.17 on the same distribution where 2048
  draws score ≈ 0.03). The accuracy configs therefore set `n_samples: 2048`
  on every sampling baseline (nbn LW/AIS/AVI/router, pyro, pgmpy LG), a
  unit test enforces it, and every continuous-target row records the
  method's draw count in `n_posterior_samples` (a warning names baselines
  below S). The
  former 256-bin histogram TV/JSD over `[min, max]` of both samples is no
  longer computed: two draws of the same distribution scored TV ≈ 0.2 and a
  single outlier could stretch the bins. Old parquets' `tv_per_node` /
  `jsd_per_node` rows on continuous families are skipped by the paper
  aggregation (`_paper_agg.DEPRECATED_CONTINUOUS_METRICS`).

## 3. Verification scope and the noise floor

* **Discrete targets, `exact_ve`:** no reference noise. Remaining
  differences between methods are the methods' own errors.
* **`lw` references** carry Monte-Carlo error of order `1/sqrt(ESS)`:
  ≈ `1/sqrt(n_reference)` for discrete targets (e.g. ≈0.004 at the synthetic
  `n_reference=50000`, ≈0.014 at bnlearn's 5000) and ≈ `1/sqrt(2000)` ≈ 0.022
  for continuous targets. Methods cannot be distinguished below this floor.
* The sanity suite (`tests/integration/test_bnlearn_sanity.py`, Layer 3)
  cross-checks the sample-based tiers against pgmpy VE (Tier A,
  `atol=0.03`) or pgmpy likelihood weighting (Tier B, `atol=0.05`) on six
  networks; the exact tier is cross-checked against brute-force enumeration
  and pgmpy VE in the unit suite.

## 4. What paper §3 should say

1. **Define the oracle by tier**: exact variable elimination on the
   data-generating model for discrete targets (all synthetic-discrete and
   bnlearn-discrete queries), likelihood weighting on the data-generating
   model for continuous targets and hybrid/CLG discrete targets.
2. **State the noise floor of the sample-based tier**: ~`1/sqrt(ESS)`; quote
   the numbers above. The exact tier has none.
3. **State the verification scope** (§3).
4. **Report the `oracle` column**: every accuracy row carries its tier, and
   `rejection` rows (none in shipped benchmarks) are excluded.
