# Oracle methodology (paper §3 reference)

Source-of-truth synthesis for the paper's §3 methodology section. Transcribed
from the issue #137 investigation (2026-06-03, re-verified against master
2026-06-05). The implementation lives in `nbn/bench/core/oracle.py`; the
verification suite in `tests/integration/test_bnlearn_sanity.py`.

## 1. What the oracle is

Every accuracy metric in the paper (TV, JSD, W1, log-likelihood) is measured
against an **oracle posterior**, and the oracle's nature is foundational to
every accuracy claim: it is **sample-based (Monte-Carlo), not exact
inference**. There is no exact-inference call anywhere in the oracle path —
the reference posterior is estimated by sampling from the known
data-generating model, and the paper must state this honestly rather than
claim "exact ground truth."

This is a *defined reference*, not metaphysical truth: all methods are
measured relative to Monte-Carlo inference on the data-generating model whose
structure and parameters we control. Framed this way, the reference is fully
reproducible and its error is quantifiable — which is a stronger footing for
accuracy claims than an exactness claim that a careful reviewer would
puncture on any network where exact inference is intractable.

## 2. The two oracle functions

Both live in `nbn/bench/core/oracle.py`; both are invoked by
`AccuracyAndTiming` (`nbn/bench/measurements/accuracy_timing.py`).

### 2.1 Discrete targets — `filter_ground_truth` (rejection sampling)

Exact-match rejection on a forward-sampled joint reference pool
(`problem.ground_truth.samples`, `n_reference` rows; `BnlearnConfig` default
5000). P(target | evidence) is the empirical target distribution among pool
rows matching the evidence; continuous evidence nodes match within
`eps_factor=0.50` standard deviations. If fewer than `n_eff_min=10` rows
survive the filter, the oracle returns `None` and the cell is **absent from
the results, not zero** — consistent with Policy 3 conditioning
(`docs/v0.13-paper-figures.md` §3.3). Conditional queries on large or sparse
networks are the typical cause of too few rejection survivors.

### 2.2 Continuous / CLG targets — `forward_with_clamp_posterior_samples`

Ancestral sampling with evidence clamped, drawing `n_oracle_samples=2000`
(the `AccuracyAndTiming` constructor default, threaded to the oracle's
`n_samples`). For SCMs of the form `X_j = f_j(X_pa(j)) + ε_j` with
independent noise, clamped ancestral sampling draws from the conditional
`p(T | E=e)` (see the function docstring for the assumption); the *estimate*
remains Monte-Carlo at finite sample count.

## 3. Verification scope and the noise floor

Because the oracle is an estimator, every reported accuracy number carries an
irreducible Monte-Carlo noise floor of order `1/sqrt(n)`: ≈ `1/sqrt(5000)` ≈
**0.014** for discrete targets at the default `n_reference`, and ≈
`1/sqrt(2000)` ≈ **0.022** for continuous targets. This floor is a lower
bound on all reported accuracy metrics — methods cannot be meaningfully
distinguished below it, and §3 should quote it explicitly so readers can
interpret small inter-method gaps correctly.

How do we know the oracle itself is right? The sanity suite
(`tests/integration/test_bnlearn_sanity.py`, Layer 3) verifies it with a
**tiered reference** on six networks (asia, barley, hailfinder, link,
sangiovese, ecoli70). Tier A compares the oracle against pgmpy
`VariableElimination` on the true model — exact, SIGALRM-bounded at 60 s —
with tolerance `atol=0.03` (the oracle's MC noise dominates; the exact
reference is precise). Where exact inference times out, OOMs, or is
unsupported, Tier B falls back to pgmpy `likelihood_weighted_sample`
(N=10000) at `atol=0.05`. On the six-network subset, exact sufficed
throughout — including barley, hailfinder, and link's marginal — but on
paper-scale networks the fallback tier is the realistic regime, and there
the honest framing is **"two sample-based estimates agreeing within their
combined noise floor,"** not "verified against exact truth."

This framing is the answer to the reviewer question the section exists for:
*"how do you know your accuracy numbers are correct, especially on large
networks?"* The defense is a quantified error floor plus cross-checks
against exact inference everywhere it is feasible — being upfront that the
reference is Monte-Carlo is far stronger than an overclaim.

## 4. What paper §3 should say

1. **Define the oracle as a Monte-Carlo reference**, not "exact ground
   truth": rejection sampling (discrete) / clamped ancestral sampling
   (continuous) from the data-generating model.
2. **State the noise floor**: MC error ~`1/sqrt(n_reference)` (discrete) /
   ~`1/sqrt(n_oracle_samples)` (continuous) lower-bounds all reported
   accuracy metrics; quote the numbers (≈0.014 at n_reference=5000).
   Methods cannot be distinguished below this floor.
3. **State the verification scope**: verified against pgmpy exact VE where
   feasible (asia, barley, hailfinder, link's marginal — all within the
   oracle's MC band, atol≈0.03); against likelihood weighting where exact is
   infeasible (atol≈0.05). Note that cells where the oracle returns `None`
   (too few rejection survivors) are absent, not zero.
4. **Frame the ground truth as a defined reference**: all methods are
   measured relative to Monte-Carlo inference on the known data-generating
   model.
