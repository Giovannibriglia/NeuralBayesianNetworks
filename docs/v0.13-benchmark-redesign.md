# v0.13 Benchmark Redesign

**Date:** 2026-05-23
**Status:** PROPOSED — investigation document, no implementation yet
**Cross-references:** #73 (bnlearn networks), #74 (topology-aware query selection),
#107 (17× re-fit per cell), #109 (this redesign — umbrella issue)

---

## §1. Motivation and Goals

### 1.1 Why restructure now

The investigation phase (v0.6b–v0.12) was deliberately exploratory: the
goal was to exercise all baseline methods, surface crashes and correctness
bugs, and establish that the NBN family produces valid posterior estimates.
That phase is concluding. The v0.13 benchmark must serve a different
purpose: producing paper-grade data that survives reviewer scrutiny.

Three concrete drivers:

1. **Issue #107 — 17× re-fit per cell.** `_compute_inference_metrics`
   re-fits each adapter once per accuracy-query row (up to 16 rows per
   cell), in addition to the 1 fit done inside `_time_nbn_inference`.
   At scalability-benchmark scales this means fit overhead dominates the
   per-cell wall-clock 17–29×, making the scalability cliff a measure of
   "when does 17 × fit_time exceed the timeout?" not "when does inference
   slow down?" The redesign eliminates this: one fit per cell, reused for
   timing, accuracy, and scalability queries.

2. **Issue #74 — random query selection.** The current runner draws query
   targets by `random.sample(nodes, k=n_queries_per_cell)` — no structural
   awareness. This under-samples hub and cut-node queries (where inference
   engines are most stressed) and over-samples peripheral nodes (where
   every engine is fast). Paper figures must report per-role metrics, not
   a uniform-random average that hides worst-case behaviour.

3. **Issue #73 — synthetic-only.** Synthetic random DAGs have bounded,
   regular structure. Real-world BNs (ASIA, ALARM, HEPAR2, ECOLI70, …)
   have hub-and-spoke topology, uneven cardinalities, and large CPD tables.
   Canonical comparability with the BN literature requires reporting on
   them.

### 1.2 Current state and limitations

**Monolithic runner.** `benchmarking/crash_test_runner.py` is 1520 lines
handling problem generation, query selection, baseline dispatch, timing,
accuracy scoring, and output writing in a single file with no clean
internal interfaces. The two public entry points (`run_parameter_learning`,
`run_inference`) share deeply nested helper functions through module-level
globals. Adding a new benchmark type (bnlearn, scalability) currently
requires forking or patching the monolith.

**Confused timeout semantics.** `per_cell_timeout_s` wraps the entire
cell: BN generation + 17 adapter fits + all query batches + accuracy
scoring. The config comment says "per-query timeout" but the
implementation says otherwise (per #107). The scalability cliff is a
timeout artefact, not an inference artefact.

**No clean adapter protocol.** `BaselineAdapterV2` exists
(`baselines/_adapter_v2.py`) but uses a stateless/functional API:
`fit(train_data, dag, variable_kinds, epochs) -> opaque_model`, then
`query_batch_samples(opaque_model, query, n_samples)`. The opaque
`fitted_model` object is threaded through all downstream calls. The shim
wrapping (`BaselineAdapterV2Shim`) adds another indirection layer. The
redesign introduces a simpler stateful contract and removes the shim.

**Synthetic-only; no real-world DAGs.** The only `ProblemSource` is
`make_synthetic_bn(...)` in `benchmarking/synthetic.py`. The bnlearn
reader (#73) has no integration point.

**Uniform random query selection.** No topological roles. No per-role
reporting. Hub and cut-node queries are under-sampled by construction
at all DAG sizes.

### 1.3 Goals of v0.13

1. **Three benchmarks with distinct purposes** (synthetic, scalability,
   bnlearn) — each with a named YAML config, a named output artifact, and
   independent smoke tests.
2. **Query-only timing semantics** — `query_time_s` is what the timeout
   wraps and what figures plot. Fit time and accuracy-scoring time are
   recorded separately but excluded from the timeout.
3. **Topology-aware query selection** (#74) — `TopologicalAllocator`
   with default 30/25/25/20 allocation across hub / cut / terminal /
   random roles.
4. **Real-world DAGs** (#73) — `BnlearnProblemSource` loading the curated
   15-network subset.
5. **Extendability** — new problem classes and new baseline methods slot
   in without touching existing code.

### 1.4 Explicit non-goals

- **No backward compatibility with v0.6c–v0.12 parquets.** Those were
  preliminary investigation data. Figures are regenerated from new data.
- **No migration of v0.6c–v0.12 figures.** All figure scripts are rerun
  against new parquets.
- **No structure learning.** Ground-truth structures only.
- **No new query types** beyond `p(target | evidence)` for this redesign.
  `do(·)` intervention queries are a possible future Phase 6.

## §2. The Three Benchmarks

### §2.1 Synthetic (accuracy + timing)

**Purpose:** Controlled experiment on synthetic random DAGs with explicit
knobs — `n_nodes`, `edge_density`, `max_in_degree`, `cardinality`,
`fraction_continuous`. Equivalent to the current `inference_paper.yaml`
scope but with topology-aware query selection and clean timing semantics.

**Problem source:** `SyntheticProblemSource` — wraps the existing
`make_synthetic_bn(...)` in `benchmarking/synthetic.py`. No changes to
DAG generation logic.

**Query selection:** `TopologicalAllocator` with default 30/25/25/20
allocation (hub / cut / terminal / random). `query_role` column populated
in output.

**Measurement:** `AccuracyAndTiming` — per-query TV, JSD, W₁ accuracy
metrics AND `query_time_s`. Fit done once per cell, reused for all queries.

**Replaces:** `inference_paper.yaml` and `parameter_learning_paper.yaml`.
(Parameter-learning mode has 1 fit/cell already — it is absorbed into
this benchmark's fit-measurement path.)

**Output configs:** `configs/synthetic_paper.yaml`, `configs/synthetic_smoke.yaml`.

### §2.2 Scalability (timing-only, 3 heaviest-query types per cell)

**Purpose:** Characterise timing scalability per baseline under
pathological query topologies. No accuracy scoring — the selected queries
are known worst-case; accuracy is not meaningful here.

**Problem source:** `SyntheticProblemSource` (same as §2.1).

**Query selection:** `HeaviestQueryByRole` — for each cell, selects
exactly THREE queries:

| Slot | Target selection | Evidence selection |
|---|---|---|
| `heaviest_hub` | Node with largest Markov-blanket cardinality | All MB neighbours as evidence |
| `heaviest_cut` | Articulation point with max treewidth-contribution heuristic | Evidence chosen to stress the cut (parents + co-parents) |
| `longest_propagation` | Deepest node by topological depth | All root nodes as evidence (maximum propagation length) |

**Measurement:** `TimingOnly` — records `query_time_s` only; no accuracy
computation. Three rows per cell (one per query type), enabling three
separate plots.

**Output:** Three timing plots (one per query-type slot) replace the
single current scalability figure.

**Replaces:** `inference_scalability.yaml`.

**Output configs:** `configs/scalability.yaml`.

### §2.3 bnlearn (accuracy + timing, real-world DAGs)

**Purpose:** Real-world reference DAGs for canonical comparability with
the BN literature.

**Problem source:** `BnlearnProblemSource` — loads networks from the
bnlearn repository per #73. Returns `BenchmarkProblem` instances with
the same interface as `SyntheticProblemSource`; downstream pipelines
are unchanged.

**Query selection:** `TopologicalAllocator` (same as §2.1). `query_role`
column populated.

**Measurement:** `AccuracyAndTiming` (same as §2.1).

**Curated 15-network subset** (from #73):

| Family | Networks | n_nodes range |
|---|---|---|
| `discrete` | ASIA, SACHS, CHILD, ALARM, HEPAR2, ANDES, PIGS, LINK | 8 – 724 |
| `continuous_lg` | ECOLI70, MAGIC-NIAB, MAGIC-IRRI, ARTH150 | 44 – 107 |
| `hybrid` (CLG) | HEALTHCARE, SANGIOVESE, MEHRA | 7 – 24 |

`continuous_nongauss` is absent from the bnlearn repository — that family
remains synthetic-only.

**Output configs:** `configs/bnlearn_paper.yaml`, `configs/bnlearn_smoke.yaml`.

## §3. Timing Semantics (the #107 Fix, Strengthened)

This section is the normative definition. All implementation PRs and paper
sections must agree with it.

### 3.1 Definitions

| Metric | What it measures | Counted toward timeout? | In parquet? |
|---|---|---|---|
| `fit_time_s` | Wall-clock of `adapter.fit(...)` | **No** | Yes |
| `query_time_s` | Wall-clock of `adapter.query(...)` for one query | **Yes** | Yes |
| `metrics_time_s` | Wall-clock of TV/JSD/W₁ computation | **No** | Yes |

**`per_cell_timeout_s` wraps only `query_time_s`.** If a single query
call exceeds the budget, the cell is marked `timeout`; fit overhead and
scoring overhead are irrelevant to the gate.

Cell wall-clock = fit + (N × query) + metrics. Only the query portion
is gated.

Storage: with N queries per cell, the parquet contains N rows per
(cell, baseline), each with its own `query_time_s`. The `fit_time_s`
and `metrics_time_s` values are recorded identically across all
N rows of a given cell (per-cell costs, repeated for query-row
joinability).

### 3.2 Honest framing

Methods that defer work to `query()` will appear slower than methods that
do the same work during `fit()`. This is intentional: the benchmark
measures inference cost — what a user pays when querying a fitted model.

**Example:** `pgmpy-VE` compiles its junction tree inside `query()` (not
`fit()`) → that compilation time counts as query time. `nbn-cat-lw`
draws particle samples inside `query()` → query time. Methods are not
penalised for `fit()` cost.

### 3.3 How this resolves #107

The current runner fits the adapter once inside `_time_nbn_inference`
and then re-fits it up to 16 more times inside `_compute_inference_metrics`
via `_baseline_posterior_for_query`. In the redesign:

1. The runner calls `adapter.fit(problem)` **once** per cell.
2. The fitted adapter is passed to `AccuracyAndTiming.measure(...)`.
3. Every `adapter.query(q)` call is independently timed.
4. Accuracy computation (`metrics_time_s`) happens after all queries, once,
   against already-computed posteriors.

**No re-fits. Ever.**

## §4. Architecture (Composition-Based)

### 4.1 Core interfaces

```python
class ProblemSource(Protocol):
    """Produces BenchmarkProblems with ground-truth structure + CPDs."""
    def iter_problems(self, cfg: BenchmarkConfig) -> Iterator[BenchmarkProblem]:
        ...

class QuerySelector(Protocol):
    """Selects queries given a DAG and a budget."""
    def select(
        self,
        problem: BenchmarkProblem,
        n_queries: int,
        seed: int,
    ) -> list[Query]:
        ...

class Measurement(Protocol):
    """Computes per-query measurements (timing, accuracy, or both)."""
    def measure(
        self,
        problem: BenchmarkProblem,
        adapter: BaselineAdapter,
        queries: list[Query],
    ) -> list[CellResult]:
        ...

class BaselineAdapter(Protocol):
    """Stateful fit-then-query contract (replaces BaselineAdapterV2 + shim)."""
    name: str

    def fit(self, problem: BenchmarkProblem, **kwargs) -> None:
        """Fit on problem.train_data. State is stored on self."""
        ...

    def query(self, query: Query) -> Posterior:
        """Query the fitted model. This call is what gets timed."""
        ...

    def is_applicable(self, problem: BenchmarkProblem) -> bool:
        """Return False if this adapter cannot handle problem.family."""
        ...
```

Note: `is_applicable()` becomes the source of truth for applicability,
replacing the static `_BASELINE_APPLICABILITY` table in the current
`_baseline_registry.py`. The `benchmarking/core/applicability.py`
module (§5) provides the orchestration layer (skip-cascade rules,
gating, etc.) but consults per-adapter `is_applicable()` for the
baseline-vs-family decisions.

Note on the adapter API change: the current `BaselineAdapterV2` is
**stateless/functional** — `fit()` returns an opaque `fitted_model`
object that is threaded through all subsequent `query_batch_samples(fitted_model, ...)` calls. The new protocol is **stateful**: `fit()` modifies `self`; `query()` reads from `self`. This is simpler to implement, simpler to test, and removes the need for `BaselineAdapterV2Shim`. The old functional pattern was introduced to avoid a mutable-state hazard; with a clean per-cell lifecycle (one adapter instance per cell), mutable state is safe.

### 4.2 Benchmark composition

```python
@dataclass
class Benchmark:
    name: str  # "synthetic" | "scalability" | "bnlearn"
    problem_source: ProblemSource
    query_selector: QuerySelector
    measurement: Measurement
    adapters: list[BaselineAdapter]  # filtered by is_applicable() at runtime
```

The runner loop is then:

```python
for problem in benchmark.problem_source.iter_problems(cfg):
    for adapter in benchmark.adapters:
        if not adapter.is_applicable(problem):
            continue
        adapter.fit(problem)
        queries = benchmark.query_selector.select(problem, cfg.n_queries, cfg.seed)
        results = benchmark.measurement.measure(problem, adapter, queries)
        writer.write(results)
```

### 4.3 Why composition over inheritance

The alternative (one class per benchmark) would require updating all three
benchmark classes when adding a new problem type or a new selection policy.
With composition:

- **New problem class** (temporal BNs, dynamic BNs, CLT models): add a
  `ProblemSource`. All existing selectors, measurements, and adapters work
  unchanged.
- **New baseline method**: add an `adapter`. All three benchmarks pick it
  up automatically through `is_applicable()`.
- **New selection policy** (adversarial queries, curriculum): add a
  `QuerySelector`. Any benchmark can use it by swapping one line in the
  config.
- **New measurement** (calibration, sharpness): add a `Measurement`. No
  changes elsewhere.

The composition also makes unit testing trivial: each component has a
small, mockable interface.

## §6. Parquet Schema (v3, No Backward Compat)

### 6.1 Current schema (v0.12)

```
family       str   "discrete" | "continuous_lg" | "continuous_nongauss" | "hybrid"
n_nodes      int   DAG size
seed         int   RNG seed
baseline     str   e.g. "pgmpy-mle-ve", "nbn-cat-lw"
metric       str   "total_time_s" | "tv_per_node" | "jsd_per_node" | "w1_per_node"
value        float metric value
status       str   "ok" | "timeout" | "oom" | "error" | "not_supported"
n_skipped    int   queries skipped (inference-loop artifact)
error_msg    str   error text (NaN if none)
```

### 6.2 Proposed schema (v3)

```
benchmark          str   "synthetic" | "scalability" | "bnlearn"
family             str   "discrete" | "continuous_lg" | "continuous_nongauss" | "hybrid"
problem_id         str   n_nodes as string (synthetic) | network name (bnlearn, e.g. "asia")
seed               int   RNG seed (1 for bnlearn — DAG is fixed, training data resampled)
baseline           str   unchanged
query_role         str   "hub" | "cut" | "terminal" | "random" (synthetic/bnlearn)
                         "heaviest_hub" | "heaviest_cut" | "longest_propagation" (scalability)
metric             str   timing or accuracy metric name
value              float metric value
status             str   "ok" | "timeout" | "oom" | "error" | "not_supported"
fit_time_s         float wall-clock of adapter.fit() — not counted toward timeout
query_time_s       float wall-clock of adapter.query() — what timeout wraps
metrics_time_s     float wall-clock of accuracy scoring — not counted toward timeout
error_msg          str   error text (NaN if none)
```

**Removed:** `n_skipped` — was an inference-loop artifact (queries skipped
when the batch budget was exceeded). With one row per query, not meaningful.

**Changed:** `n_nodes` (int) → `problem_id` (str) unifies synthetic (where
`problem_id = str(n_nodes)`) and bnlearn (where `problem_id = "asia"`)
under one column.

### 6.3 Reasoning for the per-row breakdown

Old schema: one row per `(cell, metric)` — all timing collapsed into a
single `total_time_s`.

New schema: one row per `(cell, query)` — timing split into
`fit_time_s / query_time_s / metrics_time_s`. This makes the #107 fix
directly observable in the data (fit_time_s is recorded but excluded from
figures and the timeout gate) and enables per-role plots for both scalability
and topology-aware benchmarks.

## §7. Query Selection (#74 Integration)

Full specification in #74; this section summarises the contract
the implementation must satisfy.

### 7.1 TopologicalAllocator

Given budget `Q` and allocation fractions `{hub: 0.30, cut: 0.25,
terminal: 0.25, random: 0.20}`:

1. Compute `NodeRoles` for the DAG (MB cardinality, articulation points,
   depth + descendant-count). Time budget: <1s for n_nodes ≤ 1000.
2. Draw the per-role quota from each bucket. Evidence for each query is
   drawn from the target's structural neighbourhood (parents + co-parents
   for hubs; ancestors for terminals).
3. **Small-DAG fallback:** if a role bucket has fewer unique nodes than
   its quota, cap at `min(quota, available)` and redistribute surplus to
   the random bucket. Example: ASIA (n=8) has 1 articulation point; a
   cut quota of 4 becomes 1 cut + 3 additional random.
4. **Duplicate-query collapse:** if the total budget exceeds the number of
   unique (target, evidence) pairs possible for a role, cap at the unique
   maximum. Prevents inflated row counts on small DAGs.

### 7.2 HeaviestQueryByRole (scalability)

Always returns exactly 3 queries per cell, one per slot. The `query_role`
column distinguishes them in the parquet, enabling three separate timing
plots instead of one averaged-over-role plot. The exact metric for
"treewidth contribution" per articulation point is deferred to Phase 3
(see §10).

## §8. bnlearn Integration (#73)

Full specification in #73; this section summarises the integration contract.

### 8.1 BnlearnProblemSource

`BnlearnProblemSource.iter_problems(cfg)` reads network name(s) from
the YAML config and loads a `BenchmarkProblem` per name. The returned
object has the same interface as the synthetic problem — `dag`, `variables`,
`train_data`, `test_data`, `queries`. No changes to downstream pipelines.

File format dispatch:
- **BIF / DSC / NET** (discrete networks): text-format parsers, no R
  dependency.
- **RDA / RDS** (Gaussian and CLG networks): two options under evaluation
  (see §8.2).

Converted/cached files live in `benchmarking/problems/bnlearn_data/`.
A network is loaded once and cached as a `BenchmarkProblem` in memory for
the session; no repeated I/O.

### 8.2 Open question: pyreadr vs R-conversion fallback

The pyreadr path (load `.rda` directly in Python, no R runtime required)
could not be empirically validated against real bnlearn `bn.fit` objects
in the web-agent environment (bnlearn.com not in allowlist). **Phase 4's
first task** is the empirical resolution:

1. Fetch `ecoli70.rda` (Gaussian) and `healthcare.rda` (CLG).
2. Run `pyreadr.read_r(file)` and inspect the returned dict.
3. If pyreadr returns usable nested dicts → proceed with pyreadr.
4. If pyreadr returns opaque R blobs → commit to the R-conversion
   fallback: one-shot R script using `bnlearn::as.data.frame()` /
   `coefficients()` emitting JSON-or-NPZ per network; ship converted files
   in `bnlearn_data/`.

This decision is deliberately deferred. The rest of the redesign is
independent of which path is chosen.

## §11. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Rewriting working code introduces bugs | Phased rollout with smoke-test gates; Phase 1 is refactor-first / behavior-change-second; audit doc if non-obvious decisions are made |
| Composition pattern becomes over-engineered | Interfaces are minimal (4 methods total across all protocols); refactor only on concrete need |
| bnlearn RDA loading is fragile (pyreadr) | Phase 4's first task is empirical resolution; R-conversion fallback is fully documented and buildable |
| Scalability "heaviest" metrics are gameable (method optimises for the specific query) | Per-role plots make the metric visible; reviewers see all three slots, not a collapsed average |
| Timing semantics confuse readers ("why is method X slower than Y at small n?") | §3 documents the query-only convention; paper §5 should reference it explicitly; `fit_time_s` is visible in the parquet for anyone who wants to check |
| Stateful adapter API introduces hidden state bugs across cells | One adapter instance per cell (instantiated fresh by the runner); `fit()` always called before `query()`; runner enforces this invariant |

## §12. Decision Summary

| Question | Decision |
|---|---|
| Backward compat with v0.6c–v0.12 parquets | **No** — preliminary investigation data; regenerate all figures |
| Architecture pattern | **Composition** (Strategy pattern: ProblemSource × QuerySelector × Measurement × Adapter) |
| Adapter API shape | **Stateful** (`fit()` modifies self; `query()` reads self) — replaces stateless BaselineAdapterV2 + Shim |
| Folder structure | `benchmarking/{core,problems,selectors,measurements,adapters,configs,domains}` |
| Timing semantics | **Query-only** (`query_time_s`); fit + metrics excluded from timeout gate |
| Scalability query types | **3 per cell** (heaviest_hub, heaviest_cut, longest_propagation) → 3 separate plots |
| bnlearn loading format | **Decided in Phase 4** (pyreadr vs R-conversion) |
| Query duplicate collapse | **Cap at max unique**, redistribute surplus to random bucket |
| Small-DAG role fallback | **Cap + redistribute to random** (tested on ASIA n=8) |
| Parquet schema version | **v3** — incompatible with v0.12; `n_nodes` → `problem_id`, adds `benchmark`, `query_role`, splits `total_time_s` into `fit_time_s`/`query_time_s`/`metrics_time_s`, removes `n_skipped` |
| Rollout strategy | **5 sequential phases**, each independently smoke-testable, each a single PR |
