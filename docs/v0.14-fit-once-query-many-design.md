## Section 1: Problem statement

The speed benchmark (`nbn/bench/configs/synthetic/speed/inference_speed.yaml`,
PR #170) sweeps `batch_sizes: [1, 8, 32, 128, 512, 1024]`. The current
dispatcher (`nbn/bench/cli.py::_run_cells`) runs one full
`Runner().run()` pass per sweep value, so a batchable
`(problem, seed, baseline)` cell is **fit from scratch 6 times** — once
per batch_size — even though the fitted model is identical across sweep
values.

Fit cost measured 2026-06-07 at paper scale (n=100, n_train=20480,
epochs=20 — the config defaults):

| Baseline | fit time |
|---|---|
| nbn-cat-ve / -lw | 0.12 s |
| pgmpy / pomegranate / pyro | <0.34 s |
| nbn-lg-lw | 0.3 s |
| nbn-mdn-lw | 108 s |
| nbn-neuralcat-ve / -lw | 309 s |
| nbn-flow-lw | >900 s (still fitting when the probe was stopped) |

Discrete-table and closed-form fits are free; the gradient-fit
mechanisms (neuralcat, mdn, flow) dominate. Across the paper run
(4 families × n=100 × 5 seeds × ~13 baselines × 6 sweep values), the
**redundant** fit work (5 of every 6 fits) totals **~19+ hours**,
flow- and neuralcat-dominated. For nbn-neuralcat-ve the 309 s fit is
comparable to its whole-cell query time (~293 s at B=512), so the 6×
re-fit roughly **doubles** that baseline's wall-clock.

All four adapters' fitted state is fully picklable (adapter + model,
9–25 MB at paper scale), so no architecture option is ruled out by
serialization constraints.

## Section 2: Architecture options considered

- **Option A — fit-and-cache to disk.** First worker for a
  `(problem, seed, baseline)` serializes the fitted model; later sweep
  values load it. Smallest contract change; isolation preserved. Adds
  6× serialization (≤25 MB) + disk I/O per cell. **Rejected** for
  serialization overhead with no offsetting benefit over Option D.

- **Option B — long-lived worker pool.** Workers stay alive across cell
  invocations; fit once, many queries in the same process. Best
  amortization, but a query crash in the worker loses state for the
  remaining sweep values — **weakens the Bug-4 (PR #129) crash-isolation
  property**. Rejected.

- **Option C — hoist fit to the parent process.** Fit once in the
  parent, ship the (picklable) model to query-only worker subprocesses.
  Clean separation, but fit-crash handling moves to the parent and the
  parent holds ~25 MB per active baseline. **Considered as fallback** if
  reviewers want subprocess isolation *between* sweep values.

- **Option D (CHOSEN) — in-process sweep within one cell.** The
  cell_worker becomes sweep-aware: fit once, then loop
  `measurement.measure()` over the batch_sizes list, emitting per-value
  rows. No serialization. Subprocess isolation per
  `(problem, seed, baseline)` is preserved exactly.

**Option D rationale:** it matches the natural data structure (one fit,
many sweep values), needs no serialization despite models being
picklable, and preserves per-cell crash isolation exactly. Its failure
mode aligns with sweep semantics — a batch failure at batch_size B is
already atomic (PR #168 §4.2) and independent of the other batch_sizes.

## Section 3: Chosen architecture — Option D

### 3.1 Where the sweep lives now (PR #170)

The sweep is in `cli.py::_run_cells` (lines 116–168). For each
batch_size value it constructs a new config with each swept baseline's
`batch_size` overridden (`dataclasses.replace`), calls
`Runner().run(pass_cfg)`, and discards the iterator. The runner spawns
one subprocess per `(problem, seed, baseline, sweep_value)`, each doing
fit + query. Pinned / non-batchable baselines run only on the first
pass (`i == 0` guard).

### 3.2 Where the sweep moves

Under Option D:

- `cli.py::_run_cells` loses the outer for-loop. It calls
  `Runner().run(cfg)` **once** with the full config (batch_sizes
  embedded).
- `Runner.run` iterates `(problem, seed, baseline)` — the natural cell
  key, no longer multiplied by batch_size.
- The cell worker receives the `batch_sizes` list in its context, fits
  the adapter **once**, then loops `measurement.measure()` across
  batch_sizes.
- Each `measurement.measure()` call still processes one batch_size and
  emits rows with that batch_size stamped — the existing PR #168
  per-row behavior is untouched.

The swept-vs-pinned distinction (PR #170 §5.6: `supports_batched_queries`
flag, explicit-pin-wins) is preserved, but now resolves to a *per-cell
batch_sizes list* rather than to membership in per-pass baseline lists:

- swept baseline → `batch_sizes = cfg.batch_sizes`
- pinned / non-batchable baseline → `batch_sizes = [spec.batch_size]`
  (a length-1 sweep, i.e. its pinned value, typically 1)

### 3.3 Non-sweep configs

When `cfg.batch_sizes` is None (existing benchmarks: bnlearn,
scalability, smoke), every baseline resolves to `batch_sizes =
[spec.batch_size]` (length 1). The worker's sweep loop runs exactly
once per cell — identity behavior, no change to existing output.

## Section 4: Locked design decisions

1. **Timeout budgets independent.** `fit_timeout_s` (already exists)
   covers the single `fit()`. `per_cell_timeout_s` (already exists) is
   the inference budget **per (baseline, batch_size) pair** within the
   combined cell. A swept cell with N batch_sizes is bounded by
   `fit_timeout_s + N × per_cell_timeout_s`.

2. **Fit failure semantics.** All sweep values emit sentinel rows with
   the fit-failure status — matches current behavior (every planned
   `(problem, seed, baseline, batch_size)` gets a row).

3. **Query failure mid-sweep: sweep continues.** If query at B=512 OOMs,
   B=1024 is still attempted (it might succeed if the failure was
   transient). Per-sweep-value timing is independent.

4. **Implementation locus: worker-level sweep.** `cell_worker._run_cell`
   becomes the sweep manager — fit once, loop `measurement.measure()`
   over batch_sizes. The measurement layer stays simple (one batch_size
   per call). `cli.py::_run_cells` loses its outer sweep loop;
   `Runner.run` is called once per config.

## Section 5: Cell worker contract changes

### 5.1 Current contract (PR #168)

`cell_worker._run_cell` receives a context with:
- `problem` (BenchmarkProblem)
- `baseline_spec` (BaselineSpec) — includes `batch_size`
- `seed`
- `selector`, `measurement`
- `n_queries_per_cell`, timeouts (`fit_budget_s`, `per_cell_timeout_s`),
  `default_role`

Flow: `build_adapter` → `is_applicable` → `select_groups(batch_size=…)`
→ `adapter.fit()` → `measurement.measure(query_groups=…)` → emit rows.

### 5.2 New contract

Same inputs, plus a new context key:
- `batch_sizes: list[int]` — length 1 means no sweep; length N means
  swept. Derived by the runner from `cfg.batch_sizes` for swept
  baselines, else `[baseline_spec.batch_size]`.

`baseline_spec.batch_size` becomes a *template/default*; the actual
per-pass value comes from iterating `batch_sizes`.

New flow:
1. `build_adapter` (from `baseline_spec`)
2. `is_applicable` → if False, emit one `not_supported` sentinel per
   batch_size (pre-batch, per PR #168 §4.5) and return
3. `adapter.fit()` — **once**, timed against `fit_budget_s`
4. If fit fails (exception or over budget): emit fit-failure sentinels
   for **every** batch_size in `batch_sizes` (locked decision #2), return
5. For each `batch_size` in `batch_sizes`:
   a. `select_groups(problem, n_queries_per_cell, seed, batch_size=…)`
   b. `measurement.measure(query_groups=…, query_budget_s=per_cell_timeout_s)`
      — its own timeout per pass (locked decision #1)
   c. rows already carry the stamped batch_size (PR #168 logic); emit
6. A query failure inside one `measure()` pass produces that pass's
   error/oom/timeout rows and **does not** break the loop
   (locked decision #3)

### 5.3 `select_groups` invocation (verified safe)

`select_groups` moves from once-per-cell to N-times-per-cell (once per
sweep value). Verified 2026-06-07 that this is safe: the selector is
idempotent across calls for a fixed seed — repeated calls at the same
batch_size produce identical queries, and calls at different batch_sizes
produce the **same query set, only chunked differently**. The selectors'
internal `_cache` (NodeRoles by `(family, problem_id, seed)`) is
get-or-compute and unaffected by repeated calls. `select_groups` is
cheap; the cost lives in fit and query.

### 5.4 `batch_sizes` plumbing

The runner builds the worker context. It already passes `baseline_spec`
and timeouts; it adds `batch_sizes`, computed once per cell:
- `cfg.batch_sizes` (top-level) if the baseline is swept
  (`supports_batched_queries` and not `batch_size_pinned`)
- else `[baseline_spec.batch_size]`

The swept/pinned resolution that currently lives in `_run_cells`
(`cli.py:143-147`) moves into the runner (or a small shared helper) so
both the sweep decision and the cell key live in one place.

## Section 6: Implementation plan

### PR 1: Fit-once query-many cell worker

Single PR. Files affected:
- `nbn/bench/core/cell_worker.py` — refactor `_run_cell` to fit-once
  + sweep-loop (§5.2)
- `nbn/bench/core/runner.py` — thread `batch_sizes` through to the
  worker context; resolve swept-vs-pinned here; cells are now keyed
  `(problem, seed, baseline)` not `(…, batch_size)`
- `nbn/bench/cli.py` — remove the outer sweep loop in `_run_cells`;
  call `Runner().run(cfg)` once
- `tests/integration/test_fit_once_sweep.py` (new)
- Existing PR #170 speed smoke must produce equivalent output

Scope: ~80–150 LOC including tests.

### Tests required

1. **Fit count:** swept cell with `batch_sizes=[1, 4, 16]` → `adapter.fit`
   called exactly **once** (spy/mock adapter).
2. **Sweep rows present:** parquet has rows for each batch_size, stamped
   correctly (matches PR #170 smoke verification).
3. **Fit failure → all sentinels:** mock adapter raising in `fit()`;
   verify all of `[1, 4, 16]` get fit-failure sentinel rows.
4. **Query failure isolation:** mock adapter raising at B=4 but not B=16;
   verify B=1 ok, B=4 error/oom, B=16 ok (sweep continued).
5. **Non-sweep identity:** speed_smoke and bnlearn smoke produce
   output equivalent to the #173 baseline (modulo timing noise; exact
   rows/statuses/batch_size column identical).
6. **`fit_timeout_s` covers fit only:** slow-fit mock fires the fit
   timeout after `fit_timeout_s`, not `fit_timeout_s × N`.
7. **`per_cell_timeout_s` per batch_size:** slow-query mock; each
   batch_size pass gets its own inference budget.

## Section 8: Open questions / risks

### 8.1 Backward compatibility

The cell key changes from `(problem, seed, baseline, batch_size)` to
`(problem, seed, baseline)`, so `Runner.run` yields N× fewer cells.
Downstream consumers read parquet rows, not Runner iteration: the
batch_speed figure (PR #172) reads from parquet and groups by
`(baseline, batch_size)`, so no figure-side change is expected. The
progress-bar total (`_estimate_total_cells`) will need the cell count
recomputed without the batch_size multiplier — cosmetic, but worth
not missing.

### 8.2 Memory pressure

Holding the fitted model across N sweep values keeps it resident longer.
Peak memory is still set by the largest batch_size's intermediate
tensors (B=1024), as today. The existing `RLIMIT_AS` cap is per worker,
not per query, so it already bounds the combined cell.

### 8.3 The "transient failure" assumption (decision #3)

Continuing the sweep after a query failure assumes B=1024 might succeed
even if B=512 failed. Plausible (memory layout varies, GC may run) but
unproven. Cost of being wrong: one extra timeout per cascade-failed
sweep value. Cost of being right: data preserved when failures are
recoverable. Accept and revisit if paper-scale runs show systematic
cascades. (Note: since smaller batch_sizes are cheaper, sweeping
**ascending** means the cheap values are already emitted before an
expensive one fails — failures land where they're least costly.)

### 8.4 Worker lifetime

Combined cells run longer than individual sweep cells. nbn-flow-lw:
fit (≥15 min) + up to N × `per_cell_timeout_s` of inference could be a
60+ min worker. The SIGKILL backstops still apply at `fit_timeout_s`
(fit) and `per_cell_timeout_s` (each inference pass) — **not** across
the combined cell — per locked decision #1. Flagged for operational
awareness: a long-running worker is harder to observe mid-cell, and the
streaming JSONL is the only within-cell progress signal. The
cell-level subprocess hard-timeout backstop (`runner.py`,
`fit_budget_s + per_cell_timeout_s + buffer`) will need to grow to
`fit_budget_s + N × per_cell_timeout_s + buffer` so it doesn't fire
mid-sweep on a legitimately long cell.
