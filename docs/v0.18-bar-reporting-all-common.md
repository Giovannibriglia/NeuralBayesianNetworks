# Bar-plot reporting with "all" / "common" views

**Status:** Implemented (2026-09-13), `nbn/bench/_paper_agg.py` +
`nbn/bench/_paper_figures.py`, `nbn-bench plot`.
**Supersedes:** the line-plot figures and per-scope tables of
`docs/v0.13-paper-figures.md` (its parquet contract §2 still applies), the
auto-discovered `subsetN` views, and the batch-speed table rule "any failed
seed fails the cell" (`docs/v0.14-batched-queries-design.md`, Change B).
**Motivation:** the 2026-09-11 batch_speed run had ~14k valid pgmpy timing
rows in the discrete family and an empty pgmpy row in the table, because one
hard seed timed out, seed-skip propagated it, and the failure-first cell rule
blanked the cell. Line plots also implied a continuum on axes that are all
discrete grids (n_nodes, n_train, batch_size, network name).

## 1. Summary

Every benchmark figure is a **grouped bar plot**: one group per x value, one
bar per shown method, error bar = aggregation band across seeds. The shown
methods at each x are **all non-nbn baselines applicable to the family plus
the N best nbn methods** (`--top-nbn`, default 2). Every figure and table
comes in two views: **all** (each method over the seeds it solved, with
`k/n` reported when it solved fewer than all) and **common** (each method
over the seeds solved by every shown method at that x). Tables mirror the
plots: rows = methods, columns = x values.

## 2. Contract

### 2.1 Seed = instance

The unit of "solved / not solved" is the cell `(problem_id, seed)` with the x
column factored out:

| x axis | when | instance key |
|---|---|---|
| `batch_size` | parquet has rows with batch_size > 1 | `problem_id/seed` |
| `n_train` | >= 2 distinct n_train values | `problem_id/seed` |
| `network` | benchmark == bnlearn | `seed` |
| `n_nodes` | otherwise (synthetic) | `seed` |

### 2.2 Solved

A method solves a seed **for a metric** when the cell has >= 1 `ok` row for
that metric, no `timeout` / `oom` / `error` row for it, no failure sentinel
(`metric == "status"`) for the cell, and the reduced value is not NaN (an
`ok` row with a NaN value, e.g. pomegranate's NaN posteriors #218, is not a
result). A partially timed-out cell is therefore unsolved. `not_supported` /
`not_applicable` rows are applicability, not failure: such cells are not
attempted and such methods do not appear for that family / metric.

Per-cell value: mean over the cell's ok rows for accuracy metrics and
per-query time (`query_time`), sum for `total_query_time`, first for
`fit_time` (from `fit_time_s` rows, or the `fit_time_s` column in
parameter-learning parquets, which have no timing rows).

### 2.3 Views

- **all**: per (method, x) aggregate over the seeds the method solved;
  `k` = solved seeds, `n` = distinct seeds run at x (any method, sentinels
  included). Plots annotate `k/n` above the bar and tables append `(k/n)` to
  the cell when `k < n`; nothing is added when all seeds were solved. A
  method with `k = 0` has no bar and shows its most frequent failure code.
- **common**: `C(x)` = intersection of the solved-seed sets of the shown
  methods at x that solved at least one seed (a DNF method does not empty
  the column; a method with no cell at x, e.g. a non-batchable baseline at
  B > 1, does not participate). Each shown method is aggregated over `C(x)`.
  Plots print `|C|` under the x label; tables carry a `|C|` footer row. No
  success rate.

Aggregation across seeds: `iqm_iqr` (interquartile mean ± IQR/2, default) or
`mean_std`. A `+inf` seed value (unsmoothed-MLE recovery KL) makes the
center `+inf` (drawn as `+∞`, never bold).

### 2.4 Method selection

- Non-nbn baselines: every one attempted at x is shown.
- nbn: ranked per x on the **`all` view** (direction-aware center; ties by
  more solved seeds, then name). Methods with no solved seed rank last, so a
  DNF nbn method appears (with its failure code) only when fewer than N nbn
  methods solved anything at that x.
- The `common` view reuses exactly that selection: both views always show
  the same methods, and `C(x)` is the intersection over that fixed set.
- Slots are fixed per figure (non-nbn sorted, then the nbn methods shown
  anywhere in that figure, sorted), so a method keeps its position and colour;
  an nbn method not selected at some x simply has no bar there and reads
  `--` in the table (the caption says so).

## 3. Per benchmark

| benchmark (config) | x | metrics |
|---|---|---|
| synthetic inference (`complete/inference_complete.yaml`) | `n_nodes` | tv, jsd (discrete) / w1 (continuous), total_query_time, fit_time |
| scalability (`complete/inference_scalability_complete.yaml`) | `n_nodes` | same |
| batch speed (`speed/inference_speed.yaml`) | `batch_size` | query_time (per query); pinned baselines only at B=1 |
| parameter learning (`complete/parameter_learning_complete.yaml`) | `n_nodes` | log_likelihood, param_recovery_tv/kl, calibration_pit_ks/sd_ratio, fit_time |
| learning curves (`learning_curves/learning_curves.yaml`) | `n_train` | same as parameter learning |
| bnlearn inference (`bnlearn/complete/inference_complete.yaml`) | `network` (sorted by n_nodes; split into `_partK` files beyond 8 groups) | as synthetic inference |

Time metrics use a log y axis. `n_parameters` is no longer an axis. The
calibration-vs-accuracy divergence panel and the stacked status figure
(`success_rate.pdf`) are kept under `all/plots/`. Role / kind tables and the
`subsetN` directories are gone.

## 4. Output layout

```
<output-dir>/<benchmark>/<family>/
  all/plots/<metric>_vs_<x>.pdf      all/tables/<metric>_vs_<x>.tex
  all/plots/success_rate.pdf         all/plots/divergence_*.pdf
  common/plots/<metric>_vs_<x>.pdf   common/tables/<metric>_vs_<x>.tex
  common/common_seeds.txt            C(x) per metric and x
  selection.txt                      nbn methods shown per (view, metric, x)
```

Table cells: `0.024±0.003` / `0.024±0.003 (2/5)` (all only) / failure code /
`--`; best per column in bold (direction-aware, never a failure code); nbn
rows carry `†`; labels `tab:<bench>_<family>_<view>_<metric>_vs_<x>`.
